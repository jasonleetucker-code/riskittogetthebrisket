## 0. How this was built, and how far to trust it

* Every row comes from reading the live code path (handler -> the module that decides), not from documents. Five read-only code audits split the surface (rankings / trade / rosters+Game Day+ROS / waivers+draft+BDVM / public hub+state), and every route in `app.openapi()` (224 operations) was considered; operations that read no league scoring or config are grouped as N-A.
* **Executed vs read.** The 13 defects (carried by 12 `DEFECT` rows; row A03 carries two) each have an offline repro that was **run**: it fails for the stated reason under `--runxfail` and is pinned `xfail(strict=True)` in the new test file. The `LATENT` rows are real mechanisms found by code reading whose reach is not demonstrated today, or which need a full server fixture; their repro recipes are in section 4 and were **not** executed unless stated.
* **Production** was not exercised beyond public endpoints (`/api/leagues`, `/api/status`, `/api/draft-capital`). The served `meta.scoringFingerprint` and the box's `data/leagues/scoring_<id>.json` age need a login / box access and are **not observed**. Consequently 'FAILS CLOSED' below describes what the code does, not what production's snapshot ages currently make it do (the one behavioural datum: production `dynasty_new` draft-capital returns `rookieSource: none`).
* Frontend bridge routes under `frontend/app/api/` are development-only paths (production nginx sends `/api/` straight to FastAPI); they matter for E2E and `next dev`, not for production traffic.

**Headline findings**

1. **The core gate is sound where it is applied.** Every ranking-sharing surface that reaches `server._scoring_identity_error` (`/api/data`, overrides, `/api/terminal`, trade simulate/analyze cross-league) decides on the card fingerprint, never the label, and 503s on stale or missing evidence. The trade generators and waiver/draft/BDVM/Game Day routes never serve a non-loaded league at all. No route in the batch lets the `scoringProfile` label decide a factual scoring question.
2. **Surfaces that skipped the gate** are the defects: movers (DEFECT-03), Insider-Trading leads (DEFECT-01), the manual TE multiplier on the override path (DEFECT-02), `/api/ros/team-strength` for an unknown key (DEFECT-06). DEFECT-01 is reachable today (the leads UI sends the selected league).
3. **Two private copies of league config go stale silently**: the committed archived snapshot (Consensus Edge fit, DEFECT-05, flag off in production) and process-lifetime memos of the live-card fit (DEFECT-04). The live `dynasty_main` card changed on 21 rate keys on 2026-08-19; nothing alarmed, and `refresh_snapshot` has no scheduled caller (LATENT-09).
4. **The roster cap and the lineup ladder read different sources**: lineups prefer the live slot list, the trade-side cap reads only the registry (DEFECT-07: `dynasty_new` registry 27 vs live 24 slots).
5. **Under today's two cards, every FP-gated surface 503s for the non-default league by design** (`sf1:9e51...` vs `sf1:82a5...`); the surfaces that still answer for it are LK-only (market ledgers, intel, the draft-capital fallback) plus the defects above.

* 'CORRECT' means the code path was traced and the split holds; it is not a proof for every input. UNPROVEN rows name what is missing.
