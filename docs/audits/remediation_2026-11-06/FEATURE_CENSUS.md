## How to read this

- **"no test reference found" is NOT "untested".** It means no test file matched the recorded string rules. A test may reach the item through a helper, a fixture, a client wrapper or a dynamic path.
- **A reference is a string match, not an assertion.** Each match records how it matched (strongest first): `literal-path` / `literal-template`, `route-import` / `page-import`, `quoted-flag-name`, `env-var`, `unit-name`, `workflow-file`, `exec-script`, `template-pattern` (templated route matched with params as wildcards), `handler-name` (function name referenced; weak for generic names), `template-prefix` (static prefix of a templated route; weak), `bare-identifier` (flag name as a bare word; weak), `enumerating-file` (file that lists the whole registry; weak). Weak-only items appear in the ranked list after every zero-reference item.
- Backend route matching is by path only, not by HTTP method: a test of `GET /x` also marks `POST /x` as referenced. Page `/` is matched only by import (a bare `/` is too ambiguous).
- Flag gating on routes: `direct` = `is_enabled("flag")` in the handler body; `transitiveNameBased` = `src.api.flag_reachability` name-based over-approximation, populated only with `--transitive-flags` (slow; not run by default or by `--check`).
- Risk classes: a = mutating / auth / admin route; b = value / money / probability surface (trade/draft/faab/waiver/bdvm/valuation/ros/rankings and similar path segments); c = flag default-ON; d = scheduled job; e = other. An item is in its lowest-lettered applicable class.
