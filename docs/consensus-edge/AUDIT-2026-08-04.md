# Consensus Edge — independent audit, repair, and verification

**Date:** 2026-08-04
**Scope:** the 13 commits that implemented Consensus Edge (merged to
`main` as `54807c0d0`), audited as an adversary rather than an author.
The prior session's completion claim was treated as unverified.

---

## Executive verdict

> **Experimental and Incomplete.** Not Production Ready, and not Shadow
> Mode Only either — it is built, wired end to end, and now correct
> about what it does not know.

The feature works in the mechanical sense: every endpoint answers, the
page renders, the refusal states are reachable, the timer writes and now
labels history. What it does not have is evidence that its output is
worth acting on. The evidence it *did* have was produced on a board that
priced every IDP row on a scale that does not exist.

The `consensus_edge` feature flag was ON when this audit began. It is
now **OFF by default**, on the same pre-registered gate that had turned
it on — re-run against the repaired board.

**Nothing was deleted.** `RISKIT_FEATURE_CONSENSUS_EDGE=1` plus a
restart brings the page and endpoints back for evaluation.

## The finding that matters

`fair_value.py` builds "leave-one-out" boards: recompute the 21-source
blend with the market anchor removed, then compare the result against
that anchor. Three ways the anchor could leak back in were documented,
measured, and closed. All three ask **"does the anchor's opinion still
reach the result?"**

Nobody asked the second question: **"is the result still denominated in
the same units?"** For two row classes the answer was no.

**IDP had no scale at all.** Three IDP-only expert boards — `dlfIdp`,
`idpShow`, `fantasyProsIdp` — rank within the IDP class, and
`idpTradeCalc` builds the shared-market ladder that lifts those ordinals
into the combined offense+IDP rank space. Excluding it empties the
ladder, so those three fall back to the untranslated rank and IDP #1
votes as asset #1. Measured on the 2026-08-03 payload:

> `position_idp` sources lost a within-DL/LB/DB crosswalk. That branch
> is dead: no registered source has the scope and no row carries the
> stamp. The measurement below was right throughout; the mechanism was
> not. See ADR-025.

```
IDP rows compared: 220
median LOO/base ratio: 1.224
range: 0.45x .. 3.48x
worst: Caleb Banks 3.48x (base 1183 -> loo 4115), Nick Bosa 2.69x,
       Roquan Smith 2.58x, Fred Warner 2.56x
```

Caleb Banks was **#19 in the live Top-20 Buys** on that strength alone.

**Rookies lost their ladder.** Closing leak #2 means skipping the rookie
translation, and skipping it is what breaks the scale: the untranslated
vote says rookie #1 is asset #1.

```
offense rows compared: 487   median 0.995   range 0.92x .. 2.44x
  non-rookie (400): median 0.992  max 1.17x   <- sound; one vote leaving
  rookie      (87): median 1.009  max 2.44x   <- broken
```

### What it cost

Every measurement was re-run against the repaired board. The study
script is unchanged; only its input is.

| measurement | before repair | after repair |
|---|---|---|
| top-20 buys, 14d | +3.59%, beat random 6/7 | **−1.01%**, beat random **0/6** |
| top-20 buys, 7d | +1.51%, beat random 11/15 | **−0.55%**, beat random **0/12** |
| mispricing ρ, 14d | +0.126, 7/7 folds positive | **+0.031**, 4/6 |
| mispricing ρ, 7d | +0.089, 12/14 | **+0.040**, 8/12 |
| mispricing ρ, 30d | +0.111, 3/3 | underpowered (2 folds) |
| vs market-value benchmark, 14d | we beat it 7/7 | **it beats us 5/6** |
| `Strong Buy` bucket, 14d | +8.83%, 6/6 folds | **−1.10%**, 2/6 |

The benchmark line is the one to read twice. `marketValue` — rank the
board by price, buy the expensive end — went from ρ −0.020 to **+0.116**
when the IDP rows left the universe. Over this offseason panel expensive
offense assets outperformed their cohort, and the board's buy list skews
cheap by construction (78% of top-20 buys priced under 2000, median
1173). On the rows that survive, the board is on the wrong side of the
only benchmark that matters.

`Strong Buy` deserves its own line: it was the **best** bucket before the
repair and is the **worst** after. It was also the measurement used to
justify raising the confidence ceiling so those rows could be shown at
all. The defect did not merely add noise — it produced the finding that
changed the model.

## What was repaired, with root causes

Each of these was described *correctly* in prose while the code did
something else. That is the pattern, and it is why the repairs are
paired with tests that assert the invariant rather than the symptom.

1. **Scale integrity (P0).** `data_contract.scale_integrity_lost` asks
   the registry which scale dependencies an exclusion severed;
   `fair_value_index` refuses those rows with an explicit reason.
   The rookie half is checked per row against the row's own votes, so a
   rookie the broken source never ranked keeps his score. **Surviving
   rows: median 0.992, p95 1.015, max 1.173.** (ADR-021)

   Revised the same day (ADR-025): the guard's trigger was a registry
   FLAG, and setting `is_backbone=True` on the other cross-market IDP
   source lifted it while leaving the board bit-for-bit broken. The
   deciding gate is now `shared_market_crosswalk_failed`, which reads
   the board's own translation stamps and cannot be satisfied by a
   registry edit.

2. **Served order == measured order (P0).** ADR-018 moved the top list
   to conviction and reached `top_movers` but not `build_board` — and
   `/players` is the only endpoint the page fetches. The study measured
   an ordering no user ever saw. (ADR-022)

3. **The flag default (P0).** Derived from the committed gate rather
   than asserted, so it cannot drift in either direction without a
   measurement changing. (ADR-023)

4. **Survivorship (P1).** `forward_returns` gives every row a reason;
   every consumer then filtered on `excessReturn is not None`. Now
   counted and reported per bucket. `outcomes.py` had **no tests at
   all**; it has twelve.

5. **The snapshot store destroyed its own labels (P1).**
   `INSERT OR REPLACE` is DELETE-then-INSERT in SQLite, so every re-run
   of a labelled day nulled the `fwd_*` columns the module docstring
   promises the write path never touches. No test wrote after labelling.

6. **`label_outcomes` (P1).** Keyed on two of four PK columns; stored a
   raw return where every other measurement uses cohort-excess; required
   an exact origin+N date hit; had **zero callers**. All four fixed, and
   it now runs from the snapshot script using prices read back out of
   the store's own `market_value` column.

7. **Deployment (P2).** The CE unit was the only one in the repo without
   `User=`, so it ran as root and created a root-owned sqlite the API
   could never open. `ce_needs_install` was missing from the installer's
   daemon-reload guard. The deploy test asserted `"enable --now" in
   body`, which matched any of eleven other timers.

8. **Cache staleness (P3).** Keyed on `scrapeTimestamp|paramSetId` with
   a docstring saying nothing else invalidated it — but the ledger moves
   per trade, playerctx weekly, and `MODEL_VERSION` was absent.

9. **`leagueKey` theater (P3).** Four bridge routes and the hook sent
   it; the API never read it; `scoring_fit.py` claimed to have closed
   that gap. Removed rather than half-honoured: with a single global
   cache, honouring it would serve league A's board to league B.

10. **Store schema (P4).** Gained `conviction`, `cohort_level`,
    `source_count`, `effective_weights`, `components_zero_weight` and
    the cohort-excess columns, with an additive migration —
    `CREATE TABLE IF NOT EXISTS` is a no-op against an existing table.

11. **Frontend (P5).** `WITHHELD_LABELS` was a JS copy of the Python
    label set in the one file the anti-duplication test does not read;
    the backend now stamps `withheld`. `POSITIONS` listed 7 of the 11
    position values the board produces — PICK 144, K 19, unpositioned 12,
    T 1, i.e. **176 of 973 rows (18.1%)** unreachable by filter and
    absent from the leaders panel; it is derived from the board now.
    A 1,000-row payload sliced to 50 with no indicator now says how many
    are hidden. The payload carries `contractScrapedAt` — when the data
    was gathered — beside `generatedAt`, which is board build time.

12. **CI (P6).** `consensus-edge-revalidate.yml` re-runs the gate weekly
    and **fails on verdict drift**, which is the case nothing could see:
    the cited ρ predated `fair_value.py`'s last change by an hour and no
    test could tell.

## What is still not true

- **The panel is entirely offseason** (2026-04-16 → 2026-08-03).
  Offseason repricing is rookie hype and ADP drift; in-season repricing
  is injuries and usage. The measurements may not transfer.
- **The target is market movement, not fantasy points.** A player can be
  underpriced and score badly.
- **Six usable 14-day folds is a small sample**, and two results lean
  the other way: the sell side improved on repair (−0.31%, right sign,
  where it had been +0.02%) and the tradeable-only slice is roughly flat
  (+0.23%) rather than negative. Those are reasons to keep measuring,
  not reasons to ship.
- **Sharp Flow cannot be validated with the code as it stands.** Its
  qualified cohort is recomputed live per request and `src/sharp/` has
  no as-of concept, so a historical value cannot be reconstructed
  however much ledger data accrues.
- **Production behaviour is NOT VERIFIABLE from this repository.**

## Verification

- `pytest tests/ -q -m "not livedata"` — green
- `npx vitest run` — green
- Every measurement under `docs/measurements/consensus-edge-*` re-run
  and re-committed, so the cited numbers provably describe the shipping
  code
- New tests assert invariants rather than symptoms: served ordering ==
  measured ordering (against the running API); a quarantined row cannot
  reach `top_movers`; `write_board` after `label_outcomes` preserves
  labels; the flag default equals the committed gate's own verdict; the
  surviving board is on one scale

## Next actions

1. Let the snapshot timer accrue **in-season** dates, then re-run the
   gate. `consensus-edge-revalidate.yml` will fail on the drift, which
   is the prompt.
2. Get a source that publishes offense **and** IDP in one value pool
   under one registry key — that, not a second cross-market source, is
   what a shared-market ladder needs. Registering a second cross-market
   IDP source does **not** work and setting `is_backbone` on one is
   actively harmful; ADR-025 has the measurements.
3. Give `src/sharp/` an as-of cohort so Sharp Flow becomes measurable at
   all. Until then its 0.3 is a declared prior in a component that is
   dark outside production.
4. Consider whether a board whose buy list is structurally cheap can
   beat a cheap-vs-expensive benchmark on an offseason panel at all —
   the tradeable-only slice is the honest place to look.
